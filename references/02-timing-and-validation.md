# 容量、拆组与验收

## 唯一容量口径

每一组严格15秒，组内3—4个有效镜头。总组数按需求确定，没有10分钟、40组或其他总量上限；也没有必须超过某个总时长的下限。

| 组内主要段落 | 对白字数/15秒 | 同时要求 |
|---|---:|---|
| 争吵、报急、核验 urgent | 55—80 | 强弱变化、抢话/重音有动机，不能用无限加速塞词 |
| 普通对话 ordinary | 45—70 | 留出换人、呼吸和不能与说话并行的动作 |
| 行动、情绪 action | 20—55 | 至少3次明确的信息、关系或动作结果变化 |

统计对白汉字和英数字字符，不计标点、标签、舞台说明；金额、日期、缩写需按实际读法额外复核，数字字符数不是发声时长。不要再叠加旧“每秒至少4—5字”、旧83—105字上限或“强口播所以更快”的豁免。

在保全对白和必要行动的前提下，采用紧凑、自然的分组；相邻内容能在合规容量内完整合并时，不为延长片长拆开。不能把拆碎后的普通对白随意改标为行动/情绪段，或添加重复收拾、点头、凝视来凑15秒。

这些是规划范围，不是填词目标。不为达下限新增台词，不为压上限删台词，不把普通谈话标成争吵来通过校验。混合段落依据真实动作和情绪归类。低于下限先重排相邻组；原文很短且不可合并的特殊任务，保留原文并明确例外，不能用无变化等待填时间或虚报合规。

## 两级时间预算

**先验整组，再验每个说话窗口。** 全组70字合规，不代表把其中50字塞进开头5秒也合规。

1. 为每组确定类型、全部对白、换人次数、必须完成的动作与状态变化。
2. 把15秒分给3—4个镜头，建立实际发声窗口。一个句子可跨镜连续，镜头切了不等于声音停了。
3. 按语气、字音、轮次估算每个窗口；实际配音可测时长。若安排明显需要赶词，调整窗口、跨镜连续或拆组。
4. 反应镜头可由明确的对白、尾音、必要的呼吸或动作声、及时接入的下一句，或正在推进的必要动作承接。声音须有本场依据并与反应或行动衔接，不以无变化等待、循环环境声或无依据的音效填时。
5. 换人和自然呼吸留出发声时间；需要独立呈现的呼吸、哽咽、哭声计入时间预算，不能把同一人的持续说话与不兼容的发声安排重叠。非并行动作（吞咽、数钱核对、翻到文件页、开门后才看见某人）要有时间；能够与对白同时完成的必要动作及其声音可并行。
6. 结尾镜头也分配实际任务，不统一预留2—4秒无对白脸部停留。

例：15秒内134字、11轮对话、交钱数钱，不能靠“快说”通过。按自然语义把工作邀请与还钱分别规划，再核算每组动作。原片09:52只帮助找场次，不能据此选定40组。

## 全篇覆盖

建立原对白清单和原动作清单；把每项映射到组号/镜头。顺序完整覆盖到最后一场后，才计算N和N×15秒。清单、容量计算和检查结论不写入Excel「提示词」单元格；必要的特殊处理写入「填写说明」。

人物与行动事实先从原稿独立提取，记录原文位置、参与者、动作对象、开始与结束依据；未结束的持续关系按 `08` 跨镜、跨组继承。逐组保存人物在场、位置、持物与持续动作的起止状态，以及发生变化的依据，再决定逐镜可见情况。不能从参考图列、retention或成品正文反向生成“原稿事实”，也不能把原稿没再次提及的人物自动删去。

- 逐字核对原句及标点、说话人、顺序、声源和发生方式；原稿电话、画外对白和旁白的归属保留。“电话对话”不能改成两人面对面仍说“你怎么给我打电话”。
- 核对原稿关键行动、必要触发和结果，保留有剧情作用的声音线索及其来源；新增自然声音不能制造新事件。若核心信息与无背景音乐或无字幕要求确有冲突，按主规则处理，不自行改成新对白或新事件。
- 对原稿明确的站起、冲上前、退让、拿放、换装、转场逐项核对。
- 不把原稿已有情绪行动当“多余动作”删除；也不为镜头丰富新增剧本未授权的闪回或事实。

## 机械验收脚本

本 Skill 自带 `scripts/validate_storyboard.py`。制作完运行：

```bash
python scripts/validate_storyboard.py --xlsx 成品.xlsx --dialogue-json 原对白.json --plan-json 制作记录.json
```

路径相对本Skill根目录，或使用脚本绝对路径。原对白JSON为有序数组 `[{"speaker_id":"S1","text":"原文。"}]`；脚本接受只有原文的字符串数组，但此时不验证说话人。制作记录JSON的每组包含 `seq`、`mode`、`state_changes` 和逐镜 `shots`，例如三镜组：

```json
[{"seq":1,"mode":"ordinary","state_changes":[],"shots":[{"shot":1,"visible_subjects":[1,2,3]},{"shot":2,"visible_subjects":[1,3]},{"shot":3,"visible_subjects":[2,3]}]}]
```

`visible_subjects` 为该镜实际可见的本组Subject编号，包含人物及有身份的局部、场景和商品；画外声音或对白提及不算可见。逐镜从构图与状态记录确定，再核对最终正文，不按正文出现过哪些标签猜测。编号须有效、不重复且覆盖本组全部镜头；`action` 组的 `state_changes` 仍至少有3次明确变化。原稿事实与人物连续状态记录另行保留用于独立内容复核，不以这个可见集合替代。所有制作记录独立于Excel「提示词」单元格，不增加H3顶层字段或把清单复制为生成指令。

脚本核对十三列表头、序号、是/否、最多9个连续图片槽与路径、Subject/Picture映射、六字段、3—4个标签与时间点、对白字符数量、可选的原对白完整性和分组类型；解析retention中的Subject与Shot，检查不存在、重复、漏项和格式错误，并在提供制作记录时对照 `shots.visible_subjects`。8—9张是允许的有效输入；常规不超过7张的必要性判断由人工完成，不以7张作为程序硬上限。制作完整剧本时两个JSON均要提供，不能只运行最宽松的结构检查。

脚本不理解自由文本中的全部空间关系，不能自动判断原稿人物是否应继续在场、持续动作是否合理承接，或发现事实记录与计划一起漏掉的人物；也不能判断镜头是否真正有效、图片重要性排序、场景是否漏规划、素材是否齐备、情绪或实际语速。**结构与集合一致不等于原稿和连续性完整。** 根据下面清单再独立核对；不可把字符串统计称为实际视频验证。

## 最终人工验收

- 核对3—4个镜头的起止时间、画面和承接；每镜提供新的有效信息、表演或必要动作阶段。同一构图的静态延续不冒充新镜头，运镜写清方向与终点。
- 按逐镜发声窗口复核对白容量、换人、自然呼吸和非并行动作时间；跨镜对白明确归属。表情与语气符合该句情绪，不用机械点头、眨眼或额外手势填时间。
- 原对白与关键行动按清单完整覆盖；电话/现场、当前/回忆、站/坐等未改错。文件名不改变剧本中的年代、人物关系或事实。
- 每组回看独立原稿事实、本场最后已知状态与本组最终镜头：上一组在场者是否有去向，位置与持续动作是否接上；变更是否有依据。检查搀扶、拥抱、拉住及未完成交接的双方，包含无台词者；画外裁切不能被误作离场。这个判断不以参考图列或retention作为事实来源，不仅比较同一计划派生的几个字段。
- 参考图按需、常规不超过7张、必要时最多9张；逐镜核对必要出镜人物，包含不说话的入镜人物，不能为省槽漏人。参考图槽位、Picture、Subject与retention出镜记录一致，声线编号全片稳定；人物按全片重要性排列，商品/场景在后，原图保留4K、不缩小。
- 对照全篇场景清单逐组核对：主要、重复或承担空间连续性的场景是否已规划，相关组是否绑定，同一场景是否复用一致的环境参考；需补充视角的图是否保持同一布局。缺图须标待准备并记录受影响组，不能以未上传或压回7张为由遗漏。文字环境方案符合 `01` 的条件且在「填写说明」记录理由；计划路径、Picture/Subject与实际出镜记录一致。区分“分镜规划完整”和“素材已齐备可生成”。
- 组间开镜状态、造型、持物、驾驶职责、空间方向、景别和继承标记连续；最后一组完整可拍。
- 提示词没有背景音乐、配乐或字幕的生成指令；环境声、动作声和非语言人声有明确来源及场景依据，需要对齐动作或切镜的声音写清时机，不遮盖对白，不靠声音填满空镜。原稿人声来源与声音线索完整保留。剧情解读、设计理由、容量计算和检查结论不进入「提示词」单元格。

可见人物缺绑定、构图人数或出镜记录与实际要求矛盾、持续动作参与者无依据消失、状态变化无依据，均属于未通过项；修复或明确披露未决点后才交付，不以机械检查通过代替内容验收。

仅当错误已修复且未决项已清楚披露后交付。报告实际做过的检查；没有实测音频/视频时只报告文本与时间规划检查。
