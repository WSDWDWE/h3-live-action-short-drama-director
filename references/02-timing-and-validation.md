# 容量、制作记录与验收

## 唯一容量口径

每组严格15秒，组内3—4个有效镜头；总组数按完整剧情需要确定，无固定总时长上限或下限。

| 组内主要段落 | 对白字数/15秒 | 同时要求 |
|---|---:|---|
| 争吵、报急、核验 urgent | 55—80 | 抢接、重音有动机，不能无限加速塞词 |
| 普通对话 ordinary | 45—70 | 留出换人、呼吸和不能与说话并行的动作 |
| 行动、情绪 action | 20—55 | 至少3次明确的信息、关系或动作结果变化 |

统计对白汉字和英数字字符，不计标点、标签、舞台说明；金额、日期、缩写另按实际读法复核，字符数不等于发声时长。以本表为唯一口径，不叠加历史标准。

保全对白和必要行动，采用紧凑、自然的分组；相邻内容能在容量内合并时，不为延长片长拆开。类型按实际内容判断，不把拆碎的普通对白改标action或urgent来通过校验，也不添加重复动作填时。

这些是规划范围，不是填词目标：不为达下限加词，不为压上限删词。低于下限先重排相邻组；仅当原文很短且无法自然合并时，才记录下述容量例外。例外仍需15秒内3—4个有效镜头，不能靠等待填满，也不能虚报正常合规。

## 两级时间预算

先验整组，再验每个实际发声窗口。全组字数合规，不代表把大部分对白塞进开头几秒也合规。

1. 确定段落类型、完整对白、换人次数、必要动作与状态变化。
2. 为3—4镜分配15秒及实际发声窗口。对白可跨切连续，切镜不自动产生停顿。
3. 按语气、字音和轮次估算；如有实测配音则使用实测时长。明显需要赶词时调整窗口、连续跨切或拆组，不能只写“快说”。
4. 反应镜头承接明确对白、尾音、必要呼吸或动作声、及时接入的下一句，或正在推进的必要动作；声音须有本场依据，不用静止等待或循环环境声填时。
5. 换人、呼吸、哽咽及非并行动作占用实际时间；不能重叠同一人不兼容的发声或动作。可并行的必要动作与声音可叠对白。
6. 末镜同样有实际任务，不统一预留无对白的脸部停留。

## 制作记录与覆盖

“制作记录”是校验资料的总称，按以下逻辑区分内容，不要求为每个名称另建文件：

- **原稿依据**：从剧本独立提取有序对白、声源、进出场、关键行动及触发/结果、持续接触与持物等，保留原文位置或用户纠正依据。不得从分镜、参考槽或retention倒推。原对白导出为下述JSON。
- **连续状态**：按 `08` 保存逐组开头与结束的人物在场、位置、持物、持续动作及变更依据；补足的站位标明为制作安排，不冒充原稿事实。现场、电话、画外及仅被提及须区分。
- **逐组计划**：分配对白与行动到组/镜，记录类型、时间窗口、逐镜可见主体及说话绑定，导出为下述计划JSON。按 `01` 维护素材与场景计划。

逐项映射原对白和关键行动，覆盖到最后一场后计算N与N×15秒。保留电话/现场、当前/回忆、声音线索及其触发和结果，不新增事件；原稿的冲上前、站起、争抢、交接等不能当作冗余删除。完整事实与状态用于独立复核，不能用“可见Subject集合”替代。

制作记录不写入Excel「提示词」单元格，不另增H3字段；必要特殊处理和准备状态写「填写说明」。

## 机械验收

制作完整剧本时同时提供原对白和逐组计划，运行：

```bash
python scripts/validate_storyboard.py --xlsx 成品.xlsx --dialogue-json 原对白.json --plan-json 制作记录.json
```

脚本路径相对Skill根目录，也可使用绝对路径。原对白JSON为有序数组 `[{"speaker_id":"S1","text":"原文。"}]`；只提供字符串数组只能核对文字，不能代替完整制作的说话人核对。

计划JSON每组包含 `seq`、`mode`、`state_changes`、`speakers`、`shots`：

```json
[{"seq":1,"mode":"ordinary","state_changes":[],"speakers":{"S4":1,"S7":null},"shots":[{"shot":1,"visible_subjects":[1,2,3]},{"shot":2,"visible_subjects":[1,3]},{"shot":3,"visible_subjects":[2,3]}]}]
```

- `speakers`：本组实际说话的全片S编号映射到本组Subject编号；`null`仅用于本组未绑定、全程只出声音的人物。无对白用 `{}`。对白前独立声明说话人，绑定人物每段用 `<Subject N> (Sx)`；纯声音人物写稳定身份、`(Sx)`及明确来源，如 `off-screen`、`on the phone` 或 `voice-over`。
- `shots.visible_subjects`：每镜实际可见的本组Subject，包括人物局部、场景及商品；画外声或被提及不算可见。依据构图和连续状态填写，再对照最终正文，不能按标签出现次数猜测。镜号完整、主体编号有效且不重复。
- `action`的 `state_changes` 至少3项，分别是有意义的变化，不以重复动作凑数。
- 特殊低容量组可增加 `capacity_exception`：`{"kind":"short_source_unmergeable","reason":"为何原文短且不能自然合并","timing_review":"逐镜内容、发声窗口及必要行动如何覆盖15秒"}`。只豁免字数下限，不豁免上限、有效镜头数或action变化要求；脚本标为待复核警告，须人工核实并在「填写说明」披露。

脚本检查表头、序号、继承值、连续图槽及路径、六字段、固定格式设置、Subject/Picture与说话绑定、retention和计划的可见集合、镜号与切点、分类容量，以及提供的原对白文字和说话顺序。常规参考数量的必要性判断按 `01` 人工核对。

脚本只能验证可解析结构和声明之间的关系；不理解全部自由文本或原稿因果，不能发现事实清单和计划一起漏人，也不能证明空间连续、场景充分、镜头有效或真实语速。缺少JSON、容量例外等警告须逐项处理；零错误不等于完整验收通过。

## 独立内容复核与交付边界

- 对照原稿逐字核对对白、标点、说话人、顺序与声音来源，核对关键行动的触发与结果完整覆盖。
- 每组回看原稿依据、上一组状态和最终镜头：未离场人物有无保留，位置及未完动作有无接上；特别检查无台词者、持续接触双方与未完成交接。不得仅比较同一计划派生的参考槽和retention。
- 核对每镜构图、实际任务、切点、运镜方向与终点，复核发声窗口、换人、呼吸与非并行动作；不以点头、凝视或装饰动作填时。
- 按 `01` 核对必要人物、商品、场景及原图质量，复核Picture/Subject、局部入画、声线及出镜记录；待准备素材明确标识，区分规划完整与素材齐备可生成。
- 按 `08` 核对造型、站坐、位置、持物、左右手、驾驶职责、空间方向、未完句及动作连续性，检查继承标记和末组完整性。
- 核对无背景音乐与字幕，必要自然声音有来源、不遮对白、不制造事件；提示词不含剧情解读、创作理由和检查内容。

**可修复的制作错误必须修复后交付**，包括漏绑定、错误构图人数、对白漏改、无依据消失或位移；不能仅写“已披露”就放行。

**确实无法确定或无法兼容的原稿核心事实**才列为未决：说明冲突、受影响组和无法确定的内容，不编造。用户要求不中断时先完成不受影响部分，并明确未完成范围；此时不能宣称整篇完整或全部通过。合乎上述条件的低容量例外另行披露，不伪装成正常范围。

报告实际完成的检查与未决点；没有实测音频或视频时只报告文本与时间规划检查，不宣称成片时长、语速或效果已经验证。
